HOTEL BOOKING MANAGEMENT SYSTEM
DETAILED STAFF USER GUIDE
English reference edition — aligned with the current Vietnamese guide

===============================================================================
1. WHAT THIS APPLICATION IS FOR
===============================================================================

This is an internal desktop tool for reception staff and hotel managers. It stores
rooms, customers, reservations, real check-in/check-out facts, invoices,
maintenance schedules, dashboard data and PDF reports in a local SQLite database.

It is not a public guest booking website. It does not send real email/SMS, process
payments through a bank/card provider, replace an accounting system, or yet provide
production staff permissions. Checkout records one staff-confirmed payment method,
amount and received date, but it is not a full folio or payment-processing system.
Customer ID and phone data are personal information; do not casually share
screenshots, PDFs or database files.

delete that file to solve an ordinary mistake without a backup and authorization.

3. STATES YOU MUST UNDERSTAND
===============================================================================

Room Status states:
- Available: sellable for the date or range being viewed.
- Awaiting check-in: a reservation is due within its planned time interval, but staff
  has not checked the guest in. It is not Occupied, but it must not be booked over.
- Occupied: staff recorded a real check-in. It remains occupied until a real
  checkout is recorded.
- Cleaning: created immediately after checkout for two hours by default. Staff uses
  Mark room ready only when the room is physically ready earlier.
- Maintenance: a maintenance period has been confirmed and blocks normal use.

Reservation states:
- Upcoming: reserved, not checked in.
- Active: actually checked in.
- Completed: checked out; listed in Booking History/reporting.
- Cancelled: cancelled before actual check-in; history remains. A guest who did not
  arrive is recorded in the cancellation reason, not as a separate lifecycle state.

The program uses the local computer date. Verify computer date/time at the start
of every shift. A wrong date/time can make check-in, checkout, cancellation reasons, and reports
incorrect.

===============================================================================
4. START-OF-SHIFT CHECKLIST
===============================================================================

1. Sign in and open Dashboard.
2. Review occupied rooms, arrivals and departures.
3. Open Room Status and inspect Awaiting check-in and Occupied rooms.
4. Open Room Management and inspect pending maintenance cases.
5. Remember that “Simulated email” is an internal log only; no message was sent.
6. Before editing a customer, room or reservation, search by ID/room/booking ID
   to ensure that you selected the correct record.

===============================================================================
5. CUSTOMER MANAGEMENT
===============================================================================

The Customer page shows Document Number, Document Type, name, phone and reservation
counts. Use Search, Active/Archived, document-type and issuing-country filters before
adding a record. Click a table header to sort; its arrow shows the active direction.

Select a customer row to show Customer reservations below the list. It contains every
non-deleted booking for that guest: Upcoming, Active, Completed, and Cancelled.
The table shows room, planned dates, actual checkout where applicable,
status, and the recorded reason. This differs from Dashboard Booking History, which
only contains completed stays for the selected reporting period. This is a lookup view; use Reservation Management
for check-in, checkout, cancellation, or editing.

Adding a customer:
1. Select Add Customer.
2. Select Document Type and issuing country. The nearby hint gives an accepted
   sample or length, such as “12 digits” or “e.g. S1234567A”.
3. Enter the identity document exactly for the selected type and country.
4. Enter the guest's name consistently with their document.
5. Select phone country. Enter the local number only; do not repeat a calling code
   already shown by the selector.
6. The form removes spaces, punctuation and accidental leading local zeroes.
   Review the normalized number before saving.
7. Select Save.

Supported countries currently include Vietnam, United States, Malaysia, United
Kingdom, Japan, Singapore, South Korea, Thailand, Australia and Germany.

Duplicate messages:
- “This customer already exists.” means phone, normalized name and ID match.
- “This phone number is already used by another customer...” means another record
  already uses that phone.
- “This ID number is already linked to another customer account...” means an
  identity document already belongs to another record.

Names alone may match. When a conflict occurs, the existing customer row is
highlighted. Read it before deciding whether to correct input or use the record.

BOOKING AN EXISTING GUEST: In Reservation, type a document number, name, or phone
in Existing customer, then select the correct guest from the list. The application
fills and locks the identity/contact fields and reuses the correct record, including
a legacy record. Select `New customer — enter details manually` only for a genuinely
new guest; never change a phone or create another record merely to bypass a duplicate
warning.

Use Edit to correct name/phone. Treat Customer ID as identity; do not change it
casually. Use Archive when a customer should not receive new bookings but history
must remain. Archived customers cannot be used for new/edited reservations. Do not
delete historical customers merely to clean up a list.

===============================================================================
6. ROOM MANAGEMENT AND MAINTENANCE
===============================================================================

Room Management lets staff add rooms, filter types, inspect room details, edit room settings and manage dated maintenance.

Standard, Deluxe, and Suite use the same gallery controls. The current photo is
centered and faded edges preview the previous and next photos. Use `<` or `>` to
navigate and read `Image ... of ...` for the current position. Photos are visual
references only; system status, capacity, price, and availability are the
authoritative operational facts.

Add/Edit room:
1. Select Add Room, or select a room then Edit.
2. Confirm Room Number, Room Type and Base Price.
3. Enter subtype fee when required, for example minibar or suite premium service.
4. Use permanent availability only for a long-running administrative stop-sale.
   It is not guest occupancy or short maintenance.
5. Save and verify the correct category.

Changing current room price affects future booking quotes. Existing confirmed
bookings and issued invoices retain their historical quote/snapshot.

Maintenance:
1. Edit the intended room.
2. Choose date range and write a clear work note.
3. Save.

With no unfinished overlapping booking, maintenance becomes Confirmed and Room
Status displays Maintenance for that interval.

With an Upcoming or Active overlapping booking, the system creates “Awaiting guest
response.” The room is not immediately displayed as Maintenance, but it is held
against new conflicting bookings. “Simulated email logged” means only an internal
record was created; no real message was sent.

Staff must contact the guest through the hotel's real process and move,
reschedule or cancel affected bookings as approved. Then select Confirmation
selected for the schedule. The system checks live overlap one more time. If it
rejects confirmation, a conflicting booking still exists. Cancel selected schedule
if maintenance will not occur.

Never confirm maintenance simply because the simulated notice exists.

===============================================================================
7. CREATE A NEW RESERVATION
===============================================================================

New reservations begin from Room Status, not a separate New Reservation button.

1. Open Room Status.
2. Choose `Choose dates & times`. While Check-in is active, repeated selections
   replace only the current arrival and keep a provisional one-hour minimum stay.
   Switch to Check-out before choosing the departure date/time. Week numbers are
   hidden; all seven weekdays and all 24 hour slots should be visible.
3. Select adults/children and apply the availability filter.
4. Click an appropriate room. Room Info opens first with previous/next gallery
   controls, type, capacity, bed, hourly rate, description, and amenities.
   Closing/cancelling this review does not open the booking form.
5. Choose Booking in Room Info. Reservation opens with the room and schedule set.
6. For an existing guest, search and select Existing customer by document number,
   name, or phone. For a new guest, select `New customer — enter details manually`
   and use the country selectors and format hints.
7. Review planned check-in/check-out. Checkout must be after check-in. New
   reservations cannot start in the past.
8. Review adults and children. At least one adult is required and the total cannot
   exceed the selected room type capacity.
9. Confirm/Save.
10. Verify the new record appears as Upcoming in Reservation Management and that
   Room Status refreshed.

The program validates availability again immediately before creation. Do not assume
a room remains free merely because an older screen showed it as free.

DIALOG AND MOUSE-WHEEL CONVENTIONS:
- Functional dialogs use a pale-blue shell around the complete title/content
  surface, an opaque white interior, and fixed geometry bounded by the main window.
  Drag them by the title; they are not freely resizable.
- The mouse wheel does not change country/type/status/date/time/count/area fields,
  because the same gesture scrolls the containing page. Click or use the keyboard.
- Monetary inputs such as Base Price and Extra Fee retain wheel adjustment.

===============================================================================
8. RESERVATION MANAGEMENT
===============================================================================

Reservation Management provides search, status filter, Action legend and button
tooltips.

Editing Upcoming reservations:
Use Edit for allowed changes. The system rejects overlapping dates, archived
customer/room, invalid capacity and past arrival. After check-in, guest, room and
planned arrival are locked. Editing an Upcoming room or price-bearing detail can
refresh its quoted rate from the current room price.

Check in:
1. Locate an Upcoming booking due today.
2. Confirm the guest has physically arrived and required hotel process is done.
3. Select Check in and confirm.
4. Reservation becomes Active and Room Status becomes Occupied.

Check-in is valid only today, on/after planned arrival and before planned departure.
A booking is not Occupied solely because its arrival date arrived.

Cancel:
Use Cancel only while the reservation remains Upcoming, including when a guest has
not arrived on or after planned arrival. Enter a useful reason such as `Guest did
not arrive`. The record remains Cancelled history. There is no separate No-show
action or state. An Active stay cannot be cancelled; it must be checked out or
early checked out.

Check out and invoice:
1. Confirm the guest is actually departing.
2. Select the Active reservation and choose Check out.
3. Actual checkout cannot be before actual check-in and cannot be future. A
   same-day checkout is accepted and billed as at least one billable hour.
4. Confirm. Booking becomes Completed and the system issues one invoice from
locked rate/tax and actual duration rounded half-up to hours.
5. Verify Booking History for the selected reporting period.

Financial warning: checkout requires one positive payment method, amount and received
date. A partial amount is recorded and the invoice shows its outstanding balance.
The current scope has no deposits, multiple payments, payment-provider integration,
discounts, surcharges or refunds. Invoice issue date is not evidence of payment in
full; inspect the recorded amount and balance, then use approved accounting procedure.

===============================================================================
9. DASHBOARD, HISTORY, AND PDF
===============================================================================

Dashboard has selectable Today/week/month/year periods. It shows two different
occupancy concepts:
- Current occupancy: rooms with guests actually checked in now.
- Period occupancy to date: actual occupied room-hours from start of selected
  period through the current time divided by saleable room-hours during that elapsed time.

Do not read these as the same KPI. A property can be busy right now while period
occupancy is low, or quiet right now after a busy month.

The mini reservations panel on Dashboard keeps Guest compact so the time columns
remain readable. If a row has several action buttons, the table can scroll
horizontally to reveal the rest of the actions.

Revenue, ADR and RevPAR are invoice-based, not confirmed cash collection.
Booking History contains completed stays whose actual checkout is inside selected
range. It displays up to seven entries per page; use page buttons for more.
If a stay seems missing, first check actual checkout date and reporting range.

Export Report creates a landscape PDF in cohesive blocks: a section heading, note,
and table remain together when they fit on a page; otherwise the whole block moves
to the next page. Only a block taller than one physical page continues across pages.
The Cancelled table has a dedicated `Reason` column with the staff-recorded reason.
Confirm the range and review personal data before
printing or sharing.

9.1 STATISTICS AND INVOICE EXPLORATION
--------------------------------------

Open Statistics to visualize invoice and booking data separately from the
operational Dashboard. The page contains:
- Monthly Revenue: invoice totals grouped by month for the current year.
- Today's Revenue Structure: today's displayed room-fee and service-fee split.
- Weekly Bookings Quantity: invoice-linked bookings grouped by check-in weekday.
- Most Booked Rooms: invoice-linked bookings grouped by room type.

The Invoice List can be searched by Invoice ID or Booking ID. Use the price-range
selector and From/To payment-date fields together to narrow the displayed rows.
The default date range is the previous month through today. Hover over the action
button for its description, then select it to open the complete invoice details.

Statistics is a visualization and lookup page. Use Reservation Management for
check-in, cancellation, checkout, and other booking actions.

===============================================================================
10. WHAT NOT TO DO
===============================================================================

Do not:
- delete/replace `data/hotel_data.db` to resolve an ordinary mistake;
- enter fake ID or phone just to bypass duplicate warnings;
- mark permanent room unavailability for a short repair; use dated maintenance;
- confirm maintenance while conflicting bookings remain;
- check in a guest before arrival or check out with a future date;
- cancel an Active or Completed reservation; only Upcoming reservations can be cancelled;
- assume an invoice means the balance was paid in full;
- rely on an old screenshot/report instead of refreshing the page;
- force-close the app while saving or copy live DB during a write;
- share bootstrap credential or guest personal information.

===============================================================================
11. TROUBLESHOOTING
===============================================================================

“Room is already booked” or not in available list:
Check planned dates, Active stays, pending/confirmed maintenance and whether you
are editing the same booking. Adjacent stays are valid: one can check out on the
same date another checks in. Only overlapping intervals are blocked.

“Cannot create booking for archived customer/room”:
Restore the correct record according to policy or select an active record. Do not
create an unnecessary duplicate.

“Check-in must be recorded for today”:
Check computer date/time and actual arrival. Normal reception flow does not permit
retrospective check-in.

“Checkout date cannot be before actual check-in”:
Check that you selected the correct booking and computer date/time. Same-day checkout
is allowed and billed as at least one billable hour; actual departure must be after actual arrival.

Maintenance conflict or rejected confirmation:
A live booking still overlaps. Move/reschedule/cancel it through approved process,
then confirm again. A simulated notice is not conflict resolution.

Database error at startup:
Close the app. Do not repeatedly overwrite/delete the DB. If possible copy
`data/hotel_data.db` from the project folder as a backup and give the exact message to a developer.

Room photos are briefly loading or do not change immediately:
Allow the current action to finish, then use one previous/next action. Do not click
several navigation buttons rapidly or open many Room Info dialogs at once. If the
whole gallery remains empty after restarting, report the room type and number to a
developer. A gallery-loading problem does not mutate booking data.

===============================================================================
12. SCENARIO PLAYBOOK AND HANDOVER
===============================================================================

New guest booking:
1. Search Customer by ID/phone.
2. Reuse existing record when found; otherwise create valid customer.
3. Open Room Status, choose dates/room, create reservation.
4. Verify booking ID, room and planned dates.
5. Check in only when guest actually arrives.

Guest changes phone:
1. Search exact Customer ID.
2. Edit phone and save.
3. If conflict, review highlighted existing row.
4. Do not create another customer merely to change a phone.

Guest changes room/date before arrival:
1. Find Upcoming reservation and Edit.
2. Choose new room/date; allow system overlap/maintenance/capacity validation.
3. Confirm and reread final room/dates.
4. Do not use normal Edit to move an Active guest; that needs a future room-move
   workflow and manager direction.

Guest does not arrive:
1. Confirm reservation is still Upcoming and was not checked in.
2. Select Cancel and enter a useful reason such as `Guest did not arrive`.
3. There is no separate No-show state; do not cancel an Active or Completed stay.
4. Apply any penalty or follow-up payment through approved accounting because the
   current invoice supports only its one checkout payment entry.

Guest departs:
1. Confirm Active state.
2. Record actual checkout.
3. Confirm invoice/history.
4. Enter only the amount actually received in the checkout payment dialog; process
   any later payment through approved accounting.

Maintenance overlaps booking:
1. Schedule exact dates with a useful note.
2. Pending case and simulated notice appear.
3. Contact guest through real hotel channel.
4. Resolve bookings, then confirm schedule.
5. If rejected, a live overlap remains; do not force it.

Ask a manager/developer before early check-in or late checkout outside hotel policy,
moving an Active guest, group bookings, deleting completed booking/invoice,
additional payments/refunds/discounts, claiming real message delivery, changing existing
Customer ID, deleting/importing DB, or operating multiple copied databases.

Handover:
1. Refresh Room Status and Reservations.
2. Review Awaiting check-in, Active, today’s departures and pending maintenance.
3. Record real guest contact in approved internal channel.
4. Close the app normally.
5. Follow secure backup procedure; database backups contain PII.

ADDENDUM — IDENTITY DOCUMENTS AND PAYMENT

When creating a customer, select the document type, issuing country, and the
number shown on the original document. Use Passport for international guests.

At checkout, staff must select a payment method and enter the amount actually
received. A partial payment leaves an outstanding balance on the invoice; do
not record money that has not been received as a payment.

Phone validation covers supported formats for the ten configured countries; it
does not represent every real carrier numbering plan. Schedule maintenance only
from today onward.
